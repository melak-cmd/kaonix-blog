🚀 **Argo-CD-v3.5-Release-Candidate** is here, bringing a substantial set of improvements across **security, GitOps workflows, ApplicationSets, Helm, authentication, and platform reliability**.

This release is particularly interesting for platform teams operating Argo CD at scale, with several features targeting **multi-tenancy, supply-chain security, and large ApplicationSet deployments**.

## 🔐 Impersonation-Moves-to-Beta

User **impersonation** has graduated from alpha to beta.

Argo CD can now consistently apply the impersonated user identity to server-side operations such as:

- 👀 Viewing application logs
- 🗑️ Deleting resources
- 🔄 Synchronizing applications
- 🛡️ Enforcing user-specific permissions

This is particularly valuable for **multi-tenant Kubernetes platforms**, where operations need to respect the identity and RBAC permissions of individual users.

## 💧 Source-Hydrator-Moves-to-Beta

The **Source-Hydrator** also graduates from alpha to beta.

A notable improvement is the ability to use **separate repositories for dry and hydrated manifests**.

This enables more advanced GitOps architectures where:

- 📂 Source manifests live in one repository
- 💧 Hydrated manifests are stored in another
- 🔏 Dry-source commits can be validated for integrity
- 🚀 Only trusted sources are allowed to progress through the deployment pipeline

This makes Source Hydrator increasingly interesting for organizations implementing controlled multi-repository GitOps workflows.

## 🖥️ ApplicationSet-Gets-a-New-UI

ApplicationSets receive one of the most visible improvements in Argo CD 3.5.

The UI can now **list, filter, inspect, and visualize ApplicationSet-generated applications**.

A new **Preview-Apps** view allows teams to see which applications will be generated by an ApplicationSet before they are deployed.

This can significantly improve the experience of managing large application fleets.

## 🌐 ApplicationSet-in-Any-Namespace

ApplicationSets are now fully stable when deployed **outside the Argo CD namespace**.

This is an important improvement for multi-team environments.

Instead of forcing every team to manage ApplicationSets from a central namespace, teams can organize their GitOps resources within their own namespaces.

This enables cleaner:

- 🏢 Multi-tenancy
- 🔐 RBAC boundaries
- 👥 Team ownership
- 📦 Application organization



## ⚡ ApplicationSet-Concurrency-Control

Argo CD 3.5 introduces **ApplicationSet concurrency control**.

Teams can limit how many ApplicationSet operations are processed simultaneously, helping prevent large application fleets from overwhelming:

- ☸️ Kubernetes API servers
- 📦 Git repositories
- ⚙️ Argo CD controllers

For organizations managing **hundreds or thousands of applications**, this can provide much better control over deployment workloads.

## ⛵ Helm-4-Support

Argo CD 3.5 adds **Helm 4 support** while maintaining compatibility with existing Helm 3 deployments.

This allows platform teams to adopt the latest Helm toolchain without abandoning existing applications.

For GitOps platforms heavily based on Helm, this is an important compatibility milestone.

## 🔒 mTLS-for-Repo-Server

Security receives a major upgrade with **mutual TLS support for the Argo CD repo-server**.

Communication between the repo-server and other Argo CD components can now be protected with both:

- 🔐 Encryption
- 🪪 Mutual authentication

This strengthens the security boundary between internal Argo CD components and provides an additional layer of protection for GitOps infrastructure.

The repo-server can also generate self-signed certificates in memory for internal health checks when custom certificates are not provided.

## 🛡️ Source-Integrity-Validation

One of the most important security additions is **Source Integrity**.

Argo CD can now verify that Git sources are **signed and trusted before synchronization**.

This provides an additional defense against software supply-chain attacks by ensuring that only trusted source commits are deployed.

The feature can also be configured through the Argo CD CLI, making it easier to integrate source-integrity requirements into automated platform workflows.

## ☁️ Better-Azure-Integration

The release includes several improvements for Azure environments.

### 👥 Azure-AD-Group-Claims

Large Azure AD group memberships can now be resolved through the **Microsoft Graph API**, helping avoid authentication problems caused by oversized group claims.

### 🔑 Azure-DevOps-Service-Principal

Argo CD can also authenticate to Azure DevOps repositories using **Azure Service Principals**, reducing the need for personal access tokens.

For organizations running GitOps on Azure, these changes provide a more enterprise-friendly authentication model.

## 🌐 Gateway-API-Support-in-Network-View

The Argo CD network topology view now understands **Kubernetes Gateway API** resources.

This improves visibility for modern Kubernetes networking architectures using Gateway API instead of traditional Ingress resources.

For platform teams adopting **Gateway API + Envoy Gateway**, this is a particularly useful improvement.

## 🔎 Better-Application-Search

The Argo CD UI can now search applications by their **target revision**.

Teams can quickly identify applications deployed from a specific:

- 🌿 Git branch
- 🏷️ Git tag
- 🔖 Commit SHA

This is especially useful when troubleshooting large GitOps environments.

## 🐛 Reliability-and-Performance-Improvements

Argo CD 3.5 also contains a large collection of bug fixes and operational improvements covering:

- 📦 Kubernetes resource-size limits
- 🔄 Multi-source applications
- 🧹 Resource cleanup
- 🔐 GnuPG key handling
- 💾 Cache efficiency
- 💧 Source Hydrator race conditions
- 📊 Observability
- ⏱️ Hydrator timeout handling
- 🌿 Long Git branch names

The release also includes documentation improvements around memory tuning, sync waves, pruning, Helm hooks, and orphaned resources.

## 👨‍💻 What-It-Means-for-Platform-Teams

For Kubernetes platform engineers, Argo CD 3.5 is a particularly interesting release.

1. 🔐 **Security gets stronger.** mTLS and Source Integrity provide better protection for the GitOps supply chain.

2. 🌐 **Multi-tenancy improves.** ApplicationSets can live in individual namespaces and impersonation is moving toward production maturity.

3. 🖥️ **ApplicationSet management gets easier.** The new UI and preview capabilities provide better visibility before deployment.

4. ⚡ **Large GitOps environments become easier to control.** Concurrency limits help prevent ApplicationSets from generating excessive load.

5. ⛵ **The Helm ecosystem moves forward.** Native Helm 4 support keeps Argo CD aligned with the latest Helm tooling.

6. 🌐 **Modern Kubernetes networking is better represented.** Gateway API resources are now visible in the network topology.

## 🔮 The-Bigger-Picture

Argo CD 3.5 is more than another feature release.

The direction is clear: **Argo CD is evolving from a GitOps deployment tool into a more complete platform-engineering control plane**.

Security, multi-tenancy, application fleet management, supply-chain verification, and Kubernetes-native networking are becoming first-class parts of the platform.

> 🎯 **The-takeaway:** Argo CD 3.5 brings together **stronger security, better multi-tenancy, improved ApplicationSet management, Helm 4 support, and deeper Kubernetes integration**, making it a significant release for teams operating GitOps at scale.
